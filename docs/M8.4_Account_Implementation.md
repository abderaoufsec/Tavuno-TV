## Overview

This milestone implements the account lifecycle, subscription management, and activation flow designed in M8.3. The implementation supports both FREE_LAUNCH mode (automatic activation) and future paid model (manual activation).

## Changes Made

**File:** `tavuno-control/app/config.py`


## API Documentation

### POST /v1/auth/register

Register a new Tavuno account.

**Request:**
```json
{
  "username": "string (1-120 chars)",
  "email": "string (valid email)",
  "password": "string (min 8 chars)"
}
```

**Response (201 Created):**
```json
{
  "profile_id": 123,
  "email": "user@example.com",
  "display_name": "username",
  "status": "active" | "inactive"
}
```

**Error States:**
- `400 Bad Request` - Invalid email format
- `400 Bad Request` - Password too weak (< 8 chars)
- `409 Conflict` - Email already registered

**Behavior:**
- If `FREE_LAUNCH=true`: Creates profile with `status='active'`, creates subscription and entitlements
- If `FREE_LAUNCH=false`: Creates profile with `status='inactive'`, no subscription

---

### POST /v1/auth/login (Modified)

Authenticate and issue tokens.

**Request:**
```json
{
  "email": "string",
  "password": "string",
  "device_fingerprint": "string (8-255 chars)",
  "platform": "string (2-48 chars)"
}
```

**Response (200 OK):**
```json
{
  "access_token": "jwt-string",
  "refresh_token": "jwt-string",
  "access_expires_at": 1699000000.0,
  "refresh_expires_at": 1701678400.0,
  "profile": {
    "id": 123,
    "email": "user@example.com",
    "display_name": "username"
  }
}
```

**Error States:**
- `401 Unauthorized` - Invalid credentials (generic)
- `403 Forbidden` - `ACCOUNT_INACTIVE` (new)
- `403 Forbidden` - `DEVICE_LIMIT_REACHED`
- `403 Forbidden` - `DEVICE_REVOKED`
- `429 Too Many Requests` - Rate limit exceeded

**New Behavior:**
- Returns structured error for inactive accounts:
```json
{
  "error": "ACCOUNT_INACTIVE",
  "message": "Your account is not activated yet. Please activate your subscription from your Tavuno account."
}
```

---

### GET /v1/auth/subscription

Get current subscription and entitlements.

**Authentication:** Bearer token (access token)

**Response (200 OK):**
```json
{
  "subscription": {
    "id": 456,
    "status": "active",
    "starts_at": "2026-09-21T00:00:00Z",
    "ends_at": null
  },
  "plan": {
    "id": 1,
    "name": "Free Launch",
    "code": "free_launch",
    "max_devices": 999,
    "max_concurrent_streams": 2
  },
  "entitlements": [
    {
      "resource_type": "all",
      "resource_key": "*"
    }
  ]
}
```

**Error States:**
- `401 Unauthorized` - Invalid token

**Behavior:**
- Returns `null` for subscription/plan if no active subscription exists
- Returns empty entitlements array if no subscription

---

### POST /v1/auth/subscription/activate

Activate an account and create subscription (admin only).

**Authentication:** Bearer token (admin role required)

**Request:**
```json
{
  "profile_id": 123,
  "plan_id": 1,
  "payment_reference": "stripe_12345",
  "activation_date": "2026-09-21T00:00:00Z" (optional)
}
```

**Response (200 OK):**
```json
{
  "profile_id": 123,
  "status": "active",
  "subscription_id": 456
}
```

**Error States:**
- `401 Unauthorized` - Invalid admin token
- `403 Forbidden` - Non-admin role
- `404 Not Found` - Profile not found
- `409 Conflict` - Subscription already exists

**Behavior:**
- Updates profile status to `active`
- Creates subscription with specified plan
- Creates default entitlements (all content)
- Returns confirmation

## Account Lifecycle Flows

### FREE_LAUNCH = true (Initial Launch)

```
User opens Tavuno
  ↓
Sign Up
  ↓
POST /v1/auth/register
  ↓
Backend validates email and password
  ↓
Create profile with status='active'
  ↓
Create subscription with default plan
  ↓
Create entitlements (all content)
  ↓
Return: { profile_id, status: 'active' }
  ↓
User signs in immediately
  ↓
Access granted
```

### FREE_LAUNCH = false (Future Paid Model)

```
User opens Tavuno
  ↓
Sign Up
  ↓
POST /v1/auth/register
  ↓
Backend validates email and password
  ↓
Create profile with status='inactive'
  ↓
Return: { profile_id, status: 'inactive' }
  ↓
User signs in
  ↓
POST /v1/auth/login
  ↓
Backend checks status = 'inactive'
  ↓
Return 403 Forbidden:
  {
    "error": "ACCOUNT_INACTIVE",
    "message": "Your account is not activated yet..."
  }
  ↓
Android displays activation message
  ↓
User visits Tavuno website
  ↓
User completes payment
  ↓
Webhook calls POST /v1/auth/subscription/activate
  ↓
Backend activates account:
  - Update status='active'
  - Create subscription
  - Create entitlements
  ↓
User signs in again
  ↓
Access granted
```

## Security Considerations

**Implemented:**
- ✅ Bcrypt password hashing
- ✅ Email format validation
- ✅ Password minimum length (8 chars)
- ✅ Account enumeration protection (generic errors)
- ✅ Rate limiting on login
- ✅ Server-side authorization
- ✅ INACTIVE account status handling

**Not Implemented (Future):**
- ❌ Email verification
- ❌ Password reset
- ❌ Refresh token blacklist/rotation
- ❌ Account lockout after repeated failures
- ❌ Device certificate authentication

**Recommendations:**
1. Change `JWT_SECRET` in production
2. Implement refresh token rotation
3. Add email verification before production launch
4. Implement password reset mechanism
5. Add account lockout after repeated failures

## OwnTV Integration Notes

### Boundary Separation

**Tavuno-Owned (Server-Side):**
- Account registration and authentication
- Account status (ACTIVE/INACTIVE)
- Subscription management
- Entitlements
- Device registration and limits
- Playback authorization
- Catalog delivery

**OwnTV-Local (Client-Side):**
- UI preferences
- Local profile state
- Favorites
- Watch history
- Playback position
- Settings

### Integration Layer

OwnTV will need to implement:
1. TavunoAuthService - call `/v1/auth/register`, `/v1/auth/login`
2. TavunoSubscriptionService - call `/v1/auth/subscription`
3. TavunoDeviceService - use existing device fingerprint in login
4. Error handling for ACCOUNT_INACTIVE
5. UI for activation message display

### Registration Flow in OwnTV

```
OwnTV launches
  ↓
Check if Tavuno account exists locally
  ↓
If no account:
  - Show Sign Up screen
  - Collect username, email, password
  - Call POST /v1/auth/register
  - Store profile_id locally
  ↓
If account exists:
  - Show Sign In screen
  - Collect email, password
  - Call POST /v1/auth/login
  - Store tokens locally
  ↓
If ACCOUNT_INACTIVE error:
  - Show activation message
  - Provide link to Tavuno website
  - Disable content access
```

## Troubleshooting

### Registration Fails with 409

**Error:** Email already registered

**Solution:**
- User should use different email
- Or use password reset if they forgot password (not implemented yet)

### Login Fails with 403 ACCOUNT_INACTIVE

**Error:** Account not activated

**Solution:**
- If FREE_LAUNCH=true: Check database, status should be 'active'
- If FREE_LAUNCH=false: User must activate via payment or admin
- Use admin endpoint to activate: `POST /v1/auth/subscription/activate`

### No Subscription Created

**Error:** Registration succeeded but no subscription

**Solution:**
- Check `FREE_LAUNCH` setting
- Check `DEFAULT_PLAN_ID` is set correctly
- Verify free plan exists in database
- Check migration was run successfully

### Playback Authorization Fails

**Error:** Account is not active

**Solution:**
- Check profile status in database
- If inactive, activate via admin endpoint
- Verify playback authorization code checks status
