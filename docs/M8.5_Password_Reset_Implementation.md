# M8.5 Password Reset Implementation

**Date:** 2026-09-21
**Status:** Complete
**Objective:** Implement password reset functionality with token-based email flow

---

## Overview

This milestone implements password reset functionality allowing users to recover their accounts via email. The implementation includes token generation, secure storage in Redis, email service interface, and comprehensive testing.

**Note:** Email verification was deferred to a future milestone as it's not required for the initial launch.

### 2. Token Storage Service

**File:** `tavuno-control/app/auth/token_storage.py`

New service for managing tokens in Redis:
- `generate_token()` - Generate secure random tokens
- `store_password_reset_token()` - Store reset token with TTL
- `get_password_reset_token()` - Retrieve reset token
- `delete_password_reset_token()` - Delete reset token (single-use)
- `store_email_verification_token()` - Store verification token (future)
- `get_email_verification_token()` - Retrieve verification token (future)
- `delete_email_verification_token()` - Delete verification token (future)

**Redis Keys:**
- `password_reset:{token}` - TTL 3600 seconds (1 hour)
- `email_verification:{token}` - TTL 86400 seconds (24 hours, for future use)

**Token Generation:**
- Uses `secrets.token_urlsafe(32)` for secure random tokens
- 32 bytes = 64 hex characters
- No collision checking (collision probability negligible)

### 5. Password Reset Flow

**Request Flow:**
```
User clicks "Forgot Password"
  ↓
Enters email address
  ↓
POST /v1/auth/password-reset/request
  ↓
Backend:
  - Validate email format
  - Check if email exists (generic response)
  - Generate secure token
  - Store token in Redis (1 hour TTL)
  - Send email with reset link
  ↓
Return: 200 OK (generic message)
```

**Confirmation Flow:**
```
User receives email
  ↓
Clicks reset link
  ↓
OwnTV opens reset screen
  ↓
User enters new password
  ↓
POST /v1/auth/password-reset/confirm
  ↓
Backend:
  - Validate token exists
  - Validate token not expired
  - Validate password strength
  - Update password in database
  - Delete token (single-use)
  - Invalidate all devices (security)
  ↓
Return: 200 OK
  ↓
User can sign in with new password
```

## API Documentation

### POST /v1/auth/password-reset/request

Request a password reset email.

**Request:**
```json
{
  "email": "string (valid email)"
}
```

**Response (200 OK):**
```json
{
  "message": "If the email exists, a password reset link has been sent"
}
```

**Error States:**
- `400 Bad Request` - Invalid email format

**Behavior:**
- Always returns generic message to prevent email enumeration
- Sends email with reset link if email exists
- Does nothing if email doesn't exist
- Token expires in 1 hour

---

### POST /v1/auth/password-reset/confirm

Confirm password reset with token.

**Request:**
```json
{
  "token": "string (from email)",
  "new_password": "string (min 8 chars)"
}
```

**Response (200 OK):**
```json
{
  "message": "Password has been reset successfully"
}
```

**Error States:**
- `400 Bad Request` - Invalid or expired token
- `400 Bad Request` - Password too weak (< 8 chars)

**Behavior:**
- Validates token exists in Redis
- Validates token not expired
- Validates password strength
- Updates password in database
- Deletes token (single-use)
- Invalidates all devices (security best practice)
- User must re-authenticate on all devices

## Security Considerations

### Email Enumeration Prevention
- Always return generic message regardless of whether email exists
- Constant timing (future enhancement)
- No information leakage in error messages

### Token Security
- Secure random generation (secrets module)
- Short expiration (1 hour)
- Single-use (deleted after use)
- Stored in Redis (auto-expiring)

### Session Invalidation
- All devices revoked after password reset
- User must re-authenticate on all devices
- Prevents attackers from maintaining access

### Future Enhancements
- Rate limiting on request endpoint (5 requests per hour per email)
- CAPTCHA on request endpoint
- Resend functionality (with rate limit)
- Email template system
- SMTP integration with retry logic

## Troubleshooting

### Password Reset Request Fails

**Error:** Invalid email format

**Solution:**
- User should provide valid email address
- Validate email format on client side

### Token Invalid or Expired

**Error:** Invalid or expired token

**Solution:**
- User should request new password reset
- Token expires in 1 hour
- Token is single-use

### Password Too Weak

**Error:** Password must be at least 8 characters

**Solution:**
- User should provide stronger password
- Enforce on client side

### Email Not Received

**Error:** User reports no email received

**Solution:**
- Check EMAIL_ENABLED setting
- Check SMTP configuration
- Check spam folder
- Verify email address is correct
- Check Redis connectivity

### Devices Not Revoked

**Error:** User can still sign in on old devices after reset

**Solution:**
- Verify device revocation logic in service
- Check database for revoked_at timestamps
- Verify token deletion
